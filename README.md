# chunithm-streamkit

CHUNITHM MATE 2.50（`chusanApp.exe`, 32 位）的**只读**直播数据插件。
通过 OBS 浏览器源显示判定数量、分数、连击、曲目信息与封面。

> **只读原则**：插件只做内存读取与 inline hook 取值，不写入游戏内存、不修改判定逻辑、
> 不影响成绩与结算。

> 第一次使用建议先看 **[简易说明](说明书.md)**（安装、端口、OBS、点歌命令）。

---

## 功能

| 模块 | 说明 |
|---|---|
| **判定计数** | JUSTICE CRITICAL / JUSTICE / ATTACK / MISS 四项实时读取 |
| **分数** | inline hook 捕获，实时显示 |
| **连击 / 最大连击** | 由判定差值推断，不需要 hook |
| **曲名 / 曲师** | 内置 2292 首曲库（含全部本地更新包），超长文本自动滚动 |
| **封面** | 直接解码游戏内 DDS（DXT1/DXT5）转 PNG，带磁盘缓存 |
| **难度栏** | 6 档定数（BASIC ~ WORLD'S END），按重要度分配宽度，当前难度高亮 |
| **达成状态** | JC / AJ / FC 逐级降档，MISS 后变灰 |
| **判定流** | 实时滚动显示最近 10 次判定 |
| **状态过渡** | 选歌 / 游玩平滑切换，不做整卡抖动 |
| **双状态** | 无歌曲时显示待机牌；选歌/游玩显示曲目信息 |
| **扫码登录** | B站 二维码登录，Cookie 保存到 `auth.txt`，下次启动自动加载 |
| **弹幕接收** | 原生 WebSocket + Brotli，收 `DANMU_MSG` |
| **点歌队列** | 固定 4 个候选位（空位保留）；模糊多结果时左右分栏让观众回数字选择 |
| **点歌管理** | 观众可 `取消点歌` 撤销自己的；房主可 `删歌` / `清空点歌` |
| **随机点歌** | 可按难度、定数、分类、版本随机；无条件时全范围且不指定难度 |
| **别名搜索** | 启动时在线拉取落雪别名，每 6 小时刷新；失败回退本地 |
| **队列持久化** | 队列自动写入 `songrequest.tsv`，下次启动继续加载 |
| **最近弹幕** | 独立页面 `chat.html`，显示最近 5 条，可与主插件分开摆放 |

## 安装

把 `bin` 目录里的内容整个复制到游戏根目录的 `bin` 下：

```
<游戏>\bin\chunithm_streamkit.asi          ← 插件本体
<游戏>\bin\chunithm_streamkit\
    chunithm_streamkit.ini                 ← 配置
    music_db.tsv                           ← 曲库
    music_alias.tsv                        ← 可选：点歌别名表
    web\index.html                         ← OBS 叠加层页面
    web\login.html                         ← B站 扫码登录页
    web\qrcode.min.js                      ← 二维码库（login.html 引用）
    web\chat.html                          ← 独立弹幕栏（另开浏览器源）
```

启动游戏后插件会自动加载。数据目录（日志、缓存、登录态）也会自动创建在
`<游戏>\bin\chunithm_streamkit\` 下：

```
logs\chunithm_streamkit.log    运行日志
logs\csk_hook.log              hook 安装结果
cache\<曲目ID>.png             封面缓存（可安全删除）
auth.txt                       B站 登录 Cookie（账号凭据，勿外传）
songrequest.tsv                点歌队列（开启点歌时自动保存/恢复）
```

**卸载**：删除 `bin\chunithm_streamkit.asi` 即可。

## OBS 配置

主插件（判定 / 曲目 / 点歌队列）：

1. 添加来源 → **浏览器**
2. URL：`http://127.0.0.1:8770/`
3. 宽度 **570**，高度 **约 820**（多结果选择时约 **950**）

弹幕栏（独立源，可单独摆放）：

1. 再添加一个 **浏览器** 源
2. URL：`http://127.0.0.1:8770/chat.html`
3. 宽度 **570**，高度 **约 190**

两个源都勾选「关闭源时关闭页面」避免残留连接。

## 配置要点

`chunithm_streamkit.ini`：

| 项 | 说明 |
|---|---|
| `poll_ms` | 采样周期，默认 33ms。卡顿时可调到 50 |
| `port` | HTTP 端口，默认 8770 |
| `web_root` | 相对路径按数据目录解析，一般不用改 |
| `score.hook` | 分数 hook，默认开启 |
| `music_id.hook` | 曲目 ID hook，默认开启 |
| `difficulty.hook` | 难度 hook，默认开启（决定高亮哪一档） |
| `difficulty.scan` | 全内存扫描兜底，**默认关闭**（会周期性卡顿） |

## 弹幕 / 扫码登录（可选）

默认关闭，不影响原有叠加层。启用：

```ini
[danmaku]
enabled=1
room_id=123456   ; 可填短号/UID，插件会自动解析成真实 room_id
protover=3          ; B站 当前只接受 3（Brotli）

[songrequest]
enabled=0           ; 0 = 关闭（默认）；要启用改成 1，并同时开启 [danmaku]
max=12              ; 队列容量 1-30（界面只显示前 4 张，多余显示 +N）
```

### 日志与隐私

日志只写入本机文件，不再输出到调试器/控制台；B站 WS 的 token、key、buvid
不会写进日志。

历史日志可脱敏：

```bat
python tools\scrub_log.py <日志路径>
```

日志是 UTF-8；用 CMD 查看先 `chcp 65001`，或使用 VS Code / Notepad++。

### 关闭 / 开启点歌

**永久关闭**：把 ini 里的 `[songrequest] enabled` 改成 `0`，重启游戏。

**临时关闭（不重启）**：房主在弹幕里发：

```
关闭点歌
```

重新开启：

```
开启点歌
```

也支持 `关点歌` / `停止点歌` / `开点歌` / `恢复点歌`。关闭时会取消待选择状态，
但不会立刻清空已有队列；队列界面会隐藏。

自动化/本机控制：

```bat
curl -X POST http://127.0.0.1:8770/songrequest/disable
curl -X POST http://127.0.0.1:8770/songrequest/enable
curl -X POST http://127.0.0.1:8770/songrequest/toggle
```

返回 `{"ok":true,"enabled":false}`。叠加层卡片上的「点歌板 ON/OFF」按钮
也可以直接切换；关闭点歌板会同时断开弹幕连接。

流程：

1. 打开 `http://127.0.0.1:8770/login.html`，手机 B站 扫码并确认
2. Cookie 自动写入 `auth.txt`，日志出现 `auth: cookie saved`
3. 弹幕连接自动重连，日志出现 `dm: auth reply received`
4. 直播间弹幕会记录为 `danmaku <用户名> 文本`
5. 观众发 `点歌 Grievous Lady`，插件匹配曲库并校验难度
6. 唯一结果直接入队；多个相似结果时进入选择状态，点歌人回复 `1`-`4` 继续
7. 队列固定保留 4 个候选位（空位保留），旧→新从左往右
8. 进入该曲游玩时对应卡片移到队首、显示 PLAYING 并呼吸高亮，回到选歌后移除
9. 弹幕使用独立页面 `chat.html`，在主插件之外单独添加浏览器源
10. 队列变动自动保存到 `songrequest.tsv`，下次启动且点歌开启时自动恢复

匹配规则：忽略大小写/空格/常见标点；标题精确 > 前缀 > 包含，其次曲师；
支持 1–2 个字符的拼写误差（中英文都支持，如 `grevous lady`、`蚊子小提琴`），
多个接近结果会进入候选选择。
纯数字按曲目 ID。英文缩写会展开（如 `we're` → `we are`），所以
`点歌 we are back` 能命中 `WE'RE BACK!!`。可在末尾指定难度：

```
点歌 Grievous Lady MASTER
点歌 Grievous Lady [EXPERT]
点歌 Grievous Lady 大师
```

也支持难度写在前面（空格分隔或紧挨）：

```
点歌 MASTER Grievous Lady
点歌 [EXPERT] Grievous Lady
点歌 紫 larva
点歌 紫larva
点歌 黑larva
```

颜色/难度对应：绿 = BASIC、黄 = ADVANCED、红 = EXPERT、紫 = MASTER、黑 = ULTIMA。

紧挨写法支持中文单字颜色 + 任意曲名，例如 `紫larva`、`紫创造`；
如果整段本身就是一个精确曲名（例如 `紫苑`），会优先按整首匹配，不拆难度。

未指定难度时卡片为灰色 3px 边框（与主面板难度分栏同粗）；指定后边框与难度文字
使用对应难度颜色。游玩中的卡片会移到队首，显示 PLAYING 并呼吸高亮。

**难度校验**：指定难度但该曲没有对应谱面时，会提示「该曲没有 MASTER 难度」并拒绝入队。

**多结果选择**：当标题相近/同名导致多个候选时，队列整体缩到左侧（只留曲绘与
难度色边框），右侧列出候选（序号、曲绘、曲名、曲师、可用难度）。点歌人回复
`1`-`4` 选择，其他人回复无效；60 秒未选择自动取消。

### 别名搜索

插件启动后会在后台自动拉取落雪查分器的 CHUNITHM 别名接口：

```
https://maimai.lxns.net/api/v0/chunithm/alias/list
```

- 启动时拉一次，长时间开播每 **6 小时**刷新
- 失败时回退到本地 `music_alias.tsv`，不影响点歌
- 日志：`online aliases merged: +N, total M`

本地文件格式（可选）：

```
<歌曲ID><TAB><别名1><TAB><别名2>…
```

例如 `751	gg	格雷`。别名参与模糊匹配（精确 > 前缀 > 包含）。

离线导入工具（合并 ChunithmUtil + 落雪）：

```bat
python tools\import_aliases.py --db <music_db.tsv> --out <music_alias.tsv>
```

水鱼查分器目前没有公开的 CHUNITHM 别名接口（只提供 B50），所以没有接入。

这些数据不是本项目资产，且未声明可再分发许可证，所以**发布包里不附带别名数据**；在线拉取仅供本机使用。

### 随机点歌

```
随机点歌
随机点歌 紫
随机点歌 14
随机点歌 14.5
随机点歌 14+
随机点歌 13-15
随机点歌 东方
随机点歌 AIR
点歌 随机 紫 14
```

条件可以组合：

- **难度**：`绿/黄/红/紫/黑`、`BASIC/ADVANCED/EXPERT/MASTER/ULTIMA`
- **定数**：`14`（14.0-14.9）、`14.5`、`14+`（14.5-14.9）、`13-15`、`>=14`
- **分类**：`东方`、`原创`、`niconico`、`彩绿`、`其他游戏`、`VARIETY` 等
- **版本**：`CHUNITHM`、`PLUS`、`AIR`、`STAR`、`AMAZON`、`CRYSTAL`、`PARADISE`、`NEW`、`SUN`、`LUMINOUS`、`VERSE`、`X-VERSE`、`X-VERSE-X`、`MATE`

`VERSE / X-VERSE / X-VERSE-X` 是三个不同版本，按完整名称精确匹配。
`XVERSE` = `X-VERSE`，`XVERSEX` = `X-VERSE-X`（连字符可省略）。
一次只写一个版本；多写时取第一个。

无条件 `随机点歌` 会在全曲库随机，并且**不指定难度**，只随机到歌曲；
带定数条件时会选中匹配定数的那一档难度。

分类/版本来自本地 `Music.xml`（已写入 `music_db.tsv` 后两列），不依赖网络。
可用 `tools/local_metadata.py` 从游戏目录重新生成。

弹幕指令：

| 指令 | 权限 | 说明 |
|---|---|---|
| `点歌 曲名 [难度]` | 所有人 | 加入队列 |
| `随机点歌 [条件]` / `点歌 随机 [条件]` | 所有人 | 按难度/定数/分类/版本随机点歌 |
| `取消点歌` / `撤销点歌` / `取消歌曲` | 点歌人 | 取消自己队列里的全部点歌 |
| `删歌 <序号或曲名>` / `删除歌曲` / `删除点歌` | 房主 | 删除指定点歌（序号从 1 开始） |
| `清空点歌` / `清空歌曲` / `清空队列` | 房主 | 清空整个队列 |

房主默认是扫码登录的账号；也可以在 `[songrequest] owner_uid=` 里显式指定。
非房主发删歌/清空指令只会收到“只有房主可以…”的提示。可选接口：

| 接口 | 用途 |
|---|---|
| `GET /queue` | 当前队列 JSON |
| `GET /queue/add?title=曲名&user=测试` | 手动加一条（本地调试，也支持 POST） |
| `POST /queue/clear` | 清空队列 |
| `POST /queue/remove?id=<请求ID>` | 移除单条 |

注意：

- `auth.txt` 是账号凭据明文，**不要提交/外传**；换号点登录页「刷新」重新扫码
- `room_id` 填直播间地址里的数字即可，插件会通过 room API 解析真实房间号
- 点歌功能默认关闭；关闭时不建立弹幕连接、不显示队列面板

## 曲库

`music_db.tsv` 为制表符分隔，列顺序：

```
id	曲名	曲师	BPM	BASIC	ADVANCED	EXPERT	MASTER	ULTIMA	WORLD'S END	WE标签	分类	版本
```

- 共 2292 首，覆盖 `data\A000` 与 `bin\option\*` 全部更新包
- BPM 从谱面文件 `.c2s` 的 `BPM_DEF` 字段提取
- WORLD'S END 曲目（ID 8000+）第 11 列存的是标签（止/狂/戻/改…）
- 不需要的难度列留空即可，界面会自动隐藏该格

## 已知限制

- **单曲最大连击（理论值）** 不可得，目前显示的是本局已达最大连击
- 曲目 ID / 难度通过 inline hook 获取，**游戏更新后偏移可能失效**，
  失效时会在 `logs\csk_hook.log` 记录 `bytes mismatch`，插件会自动跳过安装以保证不崩溃
- 弹幕功能依赖 `auth.txt` 里的 Cookie；Cookie 失效后需重新扫码
- 别名数据不随发布包分发：需要在线拉取，或用 `tools\import_aliases.py` 自行导入
